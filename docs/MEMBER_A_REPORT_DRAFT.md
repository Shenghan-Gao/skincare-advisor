# Member A Report Draft — Data Processing, Safety, Ethics & Limitations

## Data Sources and Preprocessing

The final implementation uses a multimodal data pipeline consisting of a facial skin image dataset for skin-type classification, Sephora product metadata and customer reviews for retrieval-augmented generation (RAG), and a small auxiliary skin-defect dataset. The original proposal emphasized product and review retrieval; the implementation was extended to include image-based skin analysis before retrieval and generation.

### Product data

The supplied Sephora archive contained 8,494 product records. We first retained records whose primary category was Skincare, leaving 2,420 candidate rows. Ingredient fields were stored as long, semi-structured text/stringified lists, so they were parsed, split on delimiters, stripped of surrounding whitespace, converted to lowercase, deduplicated, and filtered to remove empty or sentence-like fragments longer than 60 characters. Products without usable ingredient lists were removed. Price was converted to a numeric field and records with missing or non-positive prices were excluded. Rating was converted to numeric but missing ratings were left null instead of being imputed as zero. Duplicate product IDs were resolved by retaining the row with the largest review count. The resulting product table contained **2,282 unique skincare products**, including 61 products with missing ratings, with prices ranging from **$3 to $495**.

### Review and RAG evidence data

The five Sephora review files contained **1,094,411 raw reviews**. Reviews were first restricted to products retained in the cleaned product table. Text shorter than 20 characters was removed, long reviews were truncated to 1,500 characters, and an ASCII-ratio heuristic was used to retain predominantly English text. E-mail addresses, social-media handles, and phone-number patterns were replaced before retrieval. Exact normalized duplicate reviews were removed. To prevent popular products from dominating the knowledge base, reviews were ranked using available helpfulness/feedback fields and capped at 20 reviews per product. This produced **38,525 retained reviews across 2,146 products**.

The RAG knowledge base was then represented as three evidence types: product metadata descriptions, ingredient summaries, and customer reviews. Because the supplied Sephora product file did not contain a dedicated long-form description column, the description evidence was constructed only from grounded metadata fields (brand, product name, category, and Sephora highlights) rather than generating synthetic product descriptions. The final preprocessing run produced **43,089 evidence chunks**: 38,525 review chunks, 2,282 description chunks, and 2,282 ingredient chunks. Every chunk uses a globally unique evidence ID in the fixed format `{product_id}:{desc|rev|ing}:{index}`, allowing downstream reward functions to verify citations and penalize hallucinated evidence.

### Vision data

Three facial-image downloads were inspected rather than assumed to have equivalent labels. One nominal facial-condition dataset contained only 45 images from 15 individuals and did not include the required skin-type or concern labels, so it was excluded from the main CNN dataset rather than being assigned inferred labels. The main usable source contained **4,093 images** organized into oily, dry, combination, and normal skin-type classes. Two associated spreadsheets provided detailed 0–5 scores for acne, redness, open pores, fine lines/wrinkles, dehydration, and pigmentation for **200 annotation rows representing 188 unique source-image groups**.

Image preprocessing checked readability, RGB format, and minimum dimensions. Perceptual hashing (pHash) with Hamming distance <=5 was used to identify near-duplicates. We removed **163 within-class near-duplicates**. We also found near-identical images that had been assigned contradictory skin-type classes; **49 images across 26 detected cross-class pairs** were removed instead of arbitrarily choosing a label. The vendor-provided train/validation/test structure was not preserved because **786 normalized source-image groups crossed the original splits**, indicating that augmented copies of the same source image could leak between training and evaluation sets.

Concern scores were clipped to their documented 0–5 scale and binarized using a reproducible threshold: values >=2 were treated as positive and 0–1 as negative. Labels were propagated only to augmentation variants that shared the same normalized source-image ID. Missing concern labels were intentionally preserved as missing rather than being converted to negatives. The cleaned main vision dataset contains **3,881 images**, split by source-image group into **2,718 training, 584 validation, and 579 test images**. The final skin-type distribution is 1,312 normal, 1,146 dry, 1,094 oily, and 329 combination images. Detailed concern annotations are available for 495 images after safe propagation; therefore, CNN training must use a masked multi-label loss so that missing concern targets do not become false negatives or NaN losses.

A third skin-defect dataset contained 90 images from 30 individuals: 10 acne, 10 eye-bags, and 10 redness subjects, each photographed from three views. Eye-bags were excluded because they are outside the project's frozen concern taxonomy. The remaining **60 acne/redness images** were retained as an auxiliary concern-only table but were not merged into the main CNN table because they lack skin-type labels.

## Safety, Ethics, and Limitations

The application is designed as a cosmetic recommendation assistant rather than a diagnostic system. A deterministic safety layer is applied after recommendation generation. It respects user-specified avoided ingredients, filters recommendations that expose pregnancy-unsafe ingredient strings when the user indicates pregnancy, adds softer cautions for selected ingredients and potential irritants, attaches a medical disclaimer, and refuses obvious diagnosis or prescription-treatment requests. Ingredient rules are stored separately from code so that they are transparent, auditable, and reusable by both the reward function and the safety guard.

Several limitations remain. First, ingredient-name matching cannot determine clinical safety by itself because suitability depends on formulation, concentration, route of use, allergies, and individual response. The recommendation schema also exposes selected key ingredients rather than guaranteed complete product formulas, so the safety layer must be interpreted as an additional guardrail, not a medical guarantee. Second, detailed concern labels are sparse and do not cover the combination-skin class in the supplied annotation spreadsheets. This creates partial-label supervision and requires masked loss during training. Third, the main image dataset does not provide verified person identities. We can keep augmented copies of a normalized source image in one split, but we cannot guarantee that different photos of the same real person never appear across splits. Fourth, class imbalance remains, particularly for combination skin, and may affect subgroup performance.

Privacy is also important because facial images are sensitive inputs even when they are publicly available training data. The deployed system should process uploaded user selfies transiently and avoid retaining them by default. The report and demo should clearly distinguish user images from synthetic augmentation images; generated images are training aids only and should never be presented as real users. Finally, recommendation bias should be evaluated across brands, price ranges, skin types, and available demographic/skin-tone proxies where ethically and technically appropriate. The system should not imply that product popularity or review volume is equivalent to medical efficacy.
